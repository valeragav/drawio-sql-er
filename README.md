# drawio-sql-er

Плагин для [draw.io](https://www.drawio.com/), который строит ER-диаграмму из SQL.
Вставьте `CREATE TABLE …` (PostgreSQL, MySQL или SQLite), выберите файл `.sql` или
подключитесь к базе PostgreSQL — и получите аккуратную схему: каждая таблица — блок со
строками-колонками, связи идут от поля к полю в нотации «воронья лапка».

- таблицы, колонки, типы и ограничения — как в SQL (`NOT NULL`, `DEFAULT …`, `CHECK (…)`);
- первичные и внешние ключи, индексы, ENUM, представления, комментарии;
- связи раскладываются так, чтобы меньше пересекаться, и идут в обход таблиц;
- рамки-группы по префиксам имён или схемам, компактный режим для больших схем;
- обновление уже нарисованной диаграммы из новой версии схемы — таблицы остаются на местах;
- сравнение диаграммы с базой, экспорт обратно в SQL и в Mermaid для Markdown.

## Способы запуска

|                     | Docker (в браузере)                 | draw.io Desktop + `npm start`  | app.diagrams.net (консоль)                    |
| ------------------- | ----------------------------------- | ------------------------------ | --------------------------------------------- |
| Что нужно           | Docker                              | draw.io Desktop, Node.js 22.9+ | браузер                                       |
| Где работает        | `http://localhost:8080`             | окно draw.io Desktop           | https://app.diagrams.net/                     |
| Плагин подключается | сам                                 | сам                            | вставкой в консоль, после каждой перезагрузки |
| Подключение к базе  | через сервер в контейнере           | через мост в терминале         | нет                                           |
| Файлы               | скачиваются / открываются браузером | как обычно в draw.io           | как обычно на сайте                           |

Сначала скачайте проект:

```sh
git clone <адрес репозитория> drawio-sql-er
cd drawio-sql-er
```

### Docker — проще всего

```sh
docker compose up -d
```

Откройте **http://localhost:8080** — это draw.io с уже подключённым плагином.
Остановить — `docker compose down`. Диаграммы сохраняются как обычно (*File → Save*
скачивает `.drawio`), сервер ничего не хранит.

### draw.io Desktop

Нужны [draw.io Desktop](https://www.drawio.com/) (обычная версия, не из Microsoft Store:
`winget install JGraph.Draw`) и [Node.js](https://nodejs.org) 22.9 или новее.

```sh
npm install
npm start
```

Откроется draw.io с плагином. **Не закрывайте окно терминала**, пока работаете: через него
плагин подгружается в новые окна draw.io и подключается к базе. Когда закроете draw.io,
скрипт завершится сам. Открыть конкретный файл: `node scripts/start-drawio.js схема.drawio`.

Если draw.io уже был открыт обычным способом — закройте его перед `npm start`.

### На сайте app.diagrams.net

Штатно (*Extras → Plugins*) сайт подключает только встроенные плагины, но плагин можно
выполнить в консоли браузера:

1. Соберите плагин и скопируйте его в буфер обмена (в папке проекта):
   ```powershell
   npm run build
   Get-Content "dist\sql-er-plugin.js" -Raw -Encoding UTF8 | Set-Clipboard
   ```
2. Откройте https://app.diagrams.net/, нажмите **F12** → вкладка **Console**.
3. Нажмите в консоли **Ctrl+V** и **Enter**.
   - Если вместо этого появилось жёлтое предупреждение «Don't paste code…» / «Не вставляйте
     код…», напечатайте вручную `allow pasting`, нажмите **Enter**, затем снова **Ctrl+V** и **Enter**.
4. Если консоль ответила `undefined`, плагин загружен, консоль можно закрыть (F12). Красная
   ошибка — что-то пошло не так (например, в буфере не весь файл).
5. Меню **Упорядочить → Вставить → «Из SQL (ER-диаграмма)…»**.

На сайте работает всё, кроме **подключения к базе** (сайт запрещает странице обращаться к
вашему компьютеру). Плагин действует до перезагрузки вкладки — потом шаги 2–4 повторяются.
Так же можно подгрузить плагин и в draw.io Desktop: *Помощь → Open Dev Tools* → Console.

## Как пользоваться

Меню **Упорядочить → Вставить → «Из SQL (ER-диаграмма)…»** (в английском интерфейсе
*Arrange → Insert*).

1. **Источник SQL:**
   - **Вставить SQL** — вставьте текст в поле;
   - **Файл .sql** — «Выбрать файл…» или перетащите файл в поле;
   - **База PostgreSQL** — строка подключения, пароль, схемы → «Подключиться»
     (см. [«Подключение к базе»](#подключение-к-базе)).

   SQL в любом случае оказывается в поле — его можно поправить перед вставкой. Под полем
   видно, сколько найдено таблиц, связей и индексов, и предупреждения.
2. **Таблицы.** Справа — список таблиц с галочками: поиск по имени, «Все» / «Ни одной»,
   «+ связанные» (добавить соседей отмеченных). Вставляются только отмеченные; ссылки на
   остальные остаются в строках колонок (`REFERENCES …`), но без линий.
3. **Настройки:**
   - **Заменить содержимое страницы** — очистить страницу перед вставкой (иначе диаграмма
     встанет под уже нарисованным);
   - **Ограничения как в SQL** — после типа всё, что написано у колонки; если выключить —
     короткие метки `PK`, `FK`, `UQ`, `AI`;
   - **Показывать NULL** — в режиме коротких меток помечать колонки без `NOT NULL`;
   - **Показывать индексы**, **ENUM**, **Представления**, **Комментарии** — что показывать;
   - **Компактно** — в таблицах только ключи и колонки со связями, остальные свёрнуты в
     строку «⋯ ещё N колонок» (список — во всплывающей подсказке);
   - **Группы** — рамки вокруг таблиц: *по префиксам* (`course_modules`, `course_lessons`,
     `courses` → «course»), *по схемам* (`billing.*`) или *нет*.

   Внизу окна — раскрывающаяся легенда **«Обозначения на диаграмме»**.
4. **Вставить.** Отменяется одним Ctrl+Z.

### Как читать диаграмму

- 🔑 и **жирный** — первичный ключ, *курсив* — внешний ключ, 💬 — у колонки есть комментарий
  (наведите мышь), 🔍 — индекс;
- под колонками, за разделителем — ограничения таблицы (`PRIMARY KEY (a, b)`, `CHECK (…)`) и индексы;
- `||` — обязательная связь, `|o` — необязательная (внешний ключ допускает `NULL`);
- «воронья лапка» — один ко многим, `|o` на стороне ребёнка — один к одному;
- составной внешний ключ — основная линия по первой паре колонок, остальные пары — тонким пунктиром;
- ENUM — блок `«enum» имя` со значениями, тонкий пунктир к колонкам этого типа;
- представление (VIEW) — блок с пунктирной рамкой, стрелки от таблиц, из которых оно читает;
- на пересечениях линий — дуги-«мостики».

### Другие команды

Все — в меню **Упорядочить**, каждая отменяется одним Ctrl+Z.

**Обновить на странице** (кнопка в окне). Схема изменилась — загрузите новый SQL и нажмите
«Обновить на странице» вместо «Вставить»:
- таблицы остаются на своих местах и сохраняют ваши правки стиля, у них обновляются колонки,
  ограничения и индексы;
- новые таблицы встают рядом со связанными и выделяются;
- таблицы, которых больше нет в схеме, не удаляются, а становятся пунктирными и
  полупрозрачными — удалите сами, если не нужны;
- связи прокладываются заново.

Подпись таблицы можно переименовать — таблица всё равно узнаётся.

**Сравнить с диаграммой** (кнопка в окне). Загрузите схему (лучше из базы) — отчёт покажет,
чем диаграмма на странице отличается: таблицы, колонки, типы, `NOT NULL`, `DEFAULT`, ключи,
индексы, ENUM, представления, по галочке — комментарии. Сравнивается смысл, а не запись:
`INT` = `integer`, `SERIAL` = `integer DEFAULT nextval(…)`. Различия временно подсвечиваются
на диаграмме: красным — расходятся, зелёным — таблицы, которых в схеме нет.

**Экспорт в SQL / Mermaid (SQL ER)…** Собирает SQL из того, что нарисовано на странице, с
вашими правками: переименованные таблицы, исправленные или добавленные строки, связь,
нарисованная вручную между строками двух таблиц (станет `FOREIGN KEY`). Формат **Mermaid**
— для вставки схемы в Markdown (GitHub и GitLab её рисуют); галочка «для Markdown»
оборачивает текст в блок ```` ```mermaid ````. Можно скопировать или сохранить в файл.

**Перепроложить связи (SQL ER).** Передвинули таблицы — линии проложатся заново по новым
местам, рамки групп тоже подстроятся. Таблицы не должны накладываться друг на друга.

**Подсветка связей (SQL ER).** Выделите таблицу — её связи и соседние таблицы обводятся
красным. Обводка временная и диаграмму не меняет. Пункт меню включает и выключает подсветку.

## Подключение к базе

Выберите источник «База PostgreSQL». В первом поле — строка подключения, во втором — пароль,
в третьем — схемы через запятую (по умолчанию `public`), затем «Подключиться»:

```
postgres://user@host:5432/database
postgres://user@host:5432/database?sslmode=require
```

- **Docker и база на этом же компьютере** — вместо `localhost` укажите
  `host.docker.internal`: `postgres://user@host.docker.internal:5432/db` (внутри контейнера
  `localhost` — сам контейнер). База в другом контейнере — по имени сервиса в общей сети.
- Плагин **только читает структуру** (таблицы, ключи, ограничения, индексы, ENUM,
  представления, комментарии) — данные таблиц не читаются, база не меняется. Достаточно
  пользователя с правом подключения; для надёжности заведите отдельного без прав на запись.
- **Пароль не сохраняется** — ни в браузере, ни в журнале. Запоминаются только строка
  подключения без пароля и схемы.
- Выражения, которые PostgreSQL хранит по-своему, возвращаются к привычному виду:
  `= ANY (ARRAY[…])` → `IN (…)`, `'draft'::text` → `'draft'`. Остальное — как в базе
  (например, `BETWEEN` база хранит как `>= AND <=`).
- Одинаковые ограничения под разными именами показываются все, как в базе, с предупреждением.

## Что понимается из SQL

- **PostgreSQL** — `CREATE TABLE`, `ALTER TABLE … ADD …`, `CREATE INDEX`, `CREATE TYPE … AS ENUM`,
  `ALTER TYPE … ADD VALUE`, `CREATE [MATERIALIZED] VIEW`, `COMMENT ON …`; вывод
  `pg_dump --schema-only` целиком. Схемы, `"имена в кавычках"`, любые типы, `SERIAL`,
  `GENERATED … AS IDENTITY`.
- **MySQL и SQLite** распознаются сами: `` `имена` `` и `[имена]`, `AUTO_INCREMENT`,
  `COMMENT '…'`, `KEY` / `UNIQUE KEY` / `FULLTEXT KEY`, `ENGINE=…`, `WITHOUT ROWID`, дамп
  `mysqldump`.
- **Комментарии**: `COMMENT ON`, а также `--` — в конце строки колонки или строками прямо
  над колонкой / над `CREATE …`. Заголовки разделов, отделённые пустой строкой, не считаются.
- Всё остальное (функции, триггеры, `INSERT`, `GRANT` …) пропускается.

## Настройки

Необязательные настройки — в файле `.env`: скопируйте образец (`cp .env.example .env`) и
поправьте. В `.env.example` каждая переменная описана.

| Переменная          | По умолчанию | Для чего                                                      |
| ------------------- | ------------ | ------------------------------------------------------------- |
| `SQL_ER_PORT`       | `8080`       | Docker: порт в браузере                                       |
| `SQL_ER_BIND`       | `127.0.0.1`  | Docker: `0.0.0.0` — открыть в сеть (только с HTTPS, см. ниже) |
| `SQL_ER_DB`         | `on`         | Docker: `off` — выключить подключение к базе                  |
| `DRAWIO_EXE`        | —            | Desktop: путь к `draw.io.exe`, если не нашёлся сам            |
| `DRAWIO_DEBUG_PORT` | `9339`       | Desktop: служебный порт, через который подгружается плагин    |

После изменения: Docker — `docker compose up -d`, Desktop — перезапустите `npm start`.

## Вопросы и проблемы

**В меню нет пункта «Из SQL (ER-диаграмма)…».** Он в *Упорядочить → Вставить* (*Arrange →
Insert*), а не в верхнем меню «Вставка». Desktop: draw.io должен быть запущен через
`npm start`, а терминал — открыт; если draw.io был открыт раньше обычным способом — закройте
его и повторите. Docker: обновите страницу с очисткой кэша (Ctrl+F5).

**Кнопка «Подключиться» неактивна.** Подключение к базе работает только в Docker-версии и
в draw.io, запущенном через `npm start` (терминал должен быть открыт). На app.diagrams.net
его нет.

**«Сервер не отвечает» / «Превышено время ожидания».** Проверьте хост и порт. В Docker
вместо `localhost` — `host.docker.internal`. Проверьте, что PostgreSQL принимает подключения
не только с `localhost` (`listen_addresses`, `pg_hba.conf`).

**«Неверный пользователь или пароль», «База данных не найдена», «Доступ запрещён
(pg_hba.conf)»** — ошибка в строке подключения или настройках доступа PostgreSQL.

**`npm start`: «draw.io Desktop не найден».** Установите обычную версию (`winget install
JGraph.Draw`) или укажите путь в `DRAWIO_EXE`. Версия из Microsoft Store не подходит.

**`npm start`: «Нужен Node.js 22.9 или новее».** Обновите Node.js с https://nodejs.org.

**Порт 8080 занят.** Поменяйте `SQL_ER_PORT` в `.env` и выполните `docker compose up -d`.

**Линии легли криво после того, как я подвинул таблицы.** *Упорядочить → Перепроложить связи (SQL ER)*.

## Безопасность

- Плагин работает с базой **только на чтение**; каждый запрос ограничен 30 секундами, в
  списке подключений (`pg_stat_activity`) он виден как `drawio-sql-er`.
- **Docker** по умолчанию доступен только с этого компьютера. Сервер подключается к той
  базе, которую укажет открывший страницу, и пароль передаётся ему в запросе — поэтому,
  открывая доступ коллегам (`SQL_ER_BIND=0.0.0.0`), ставьте впереди прокси с HTTPS и
  авторизацией (nginx, Caddy, Traefik) или выключите подключение к базе (`SQL_ER_DB=off`).
- **`npm start`** открывает у draw.io служебный порт `127.0.0.1:9339` — из сети он
  недоступен, но пока draw.io запущен так, им может воспользоваться любая программа на этом
  компьютере. На общем компьютере подгружайте плагин через консоль.
- Разметка в подписях чужих файлов `.drawio` не выполняется.

## Ограничения

- Подключение к базе — только PostgreSQL.
- У представлений из SQL-файла нет типов колонок (их знает только база).
- Составные типы (`CREATE TYPE … AS (…)`), домены, функции и триггеры не показываются.
- `--`-комментарии есть только в тексте SQL; из базы берутся только `COMMENT ON`.
- Экспорт в SQL выдаёт синтаксис PostgreSQL, в том числе для схем из MySQL и SQLite.
- «Обновить на странице» работает для диаграмм, вставленных этим плагином.
- В Docker нет офлайн-режима draw.io; PDF сохраняется через печать браузера.
