# drawio-sql-er

Плагин для [draw.io](https://www.drawio.com/): вставляете SQL DDL (PostgreSQL; MySQL и SQLite —
тоже) или подключаетесь к базе PostgreSQL — получаете ER-диаграмму.
Каждая таблица — отдельный блок со строками-колонками, связи идут от поля к полю в нотации «воронья лапка».

- 🔑 и **жирный** — первичный ключ, *курсив* — внешний ключ
- после типа — ограничения колонки как в SQL: `price : NUMERIC(12,2) NOT NULL CHECK (price >= 0)`
  (или короткие метки `(PK, FK, UQ, AI, NULL)` — галочка «Ограничения как в SQL» выключена)
- под колонками, за разделителем — ограничения уровня таблицы (`CHECK (…)`, `PRIMARY KEY (a, b)`,
  `FOREIGN KEY …`, в т.ч. из `ALTER TABLE … ADD CONSTRAINT`) и индексы (🔍)
- `||` — обязательный родитель, `|o` — необязательный (FK допускает NULL)
- `<` — один ко многим, `|o` на стороне ребёнка — один к одному (FK = PK или FK UNIQUE)
- таблицы раскладываются по уровням: без внешних ключей — слева, зависимые — правее;
  справочник встаёт прямо перед своими «детьми»; циклы ссылок разрываются так, чтобы
  «против течения» шло как можно меньше связей
- порядок таблиц в столбце подбирается так, чтобы линии меньше пересекались: по строкам,
  с которыми таблица связана, с перестановками соседей; из нескольких вариантов берётся тот,
  где у проложенных линий меньше всего пересечений
- связь через несколько столбцов проходит через заранее оставленные «окна» между таблицами
- группы (рамки) — блоки на своих столбцах: группы на разных столбцах стоят рядом
- таблицы без связей — сеткой под схемой
- перечисления (`CREATE TYPE … AS ENUM`) — блоки `«enum» имя` со значениями; тонкий пунктир
  к колонкам этого типа (в т.ч. массивам `status[]`)
- представления (`CREATE [MATERIALIZED] VIEW`) — блоки с пунктирной рамкой, колонки из списка
  или из `SELECT`; пунктирные стрелки от таблиц из `FROM` / `JOIN`
- комментарии: `COMMENT ON TABLE / VIEW / TYPE` — мелкой курсивной строкой под заголовком,
  `COMMENT ON COLUMN` — всплывающей подсказкой (у колонки значок 💬)
- составной внешний ключ: основная линия со значками по первой паре колонок, остальные
  пары — тонким пунктиром
- длинные строки (ограничения, индексы) переносятся — таблица не шире 480 px
- связи прокладываются только под прямым углом и в обход таблиц: вертикальные участки идут
  по своим «дорожкам» между столбцами (связи из одного поля — общим «стволом»), а связи через
  столбец — по горизонтальным «коридорам» между таблицами; на пересечениях — дуги-мостики
- без раскраски, стандартный стиль draw.io (нормально выглядит и в тёмной теме)

## Требования

- **draw.io Desktop** (проверено на 31.5, Windows). Версия из Microsoft Store не подходит —
  ставьте обычную: `winget install JGraph.Draw` или с [drawio.com](https://www.drawio.com/).
- **Node.js 22+** — для `npm start` (запуск draw.io с плагином и подключение к базе).
- **PostgreSQL** — только если нужна загрузка схемы из базы; достаточно прав на чтение
  каталога (`pg_catalog`), данные таблиц не читаются.

## Установка и сборка

```sh
git clone <адрес репозитория> drawio-sql-er
cd drawio-sql-er
npm install     # драйвер PostgreSQL (pg) — нужен только для загрузки схемы из базы
npm start       # собрать плагин и открыть draw.io
```

Для разработки:

```sh
npm run build   # → dist/sql-er-plugin.js
npm test
npm run check   # перед выпуском: сборка актуальна, все модули в ней, тесты проходят
```

Сам плагин (`dist/sql-er-plugin.js`) зависимостей не имеет.

## Подключение к draw.io

В актуальных версиях draw.io (проверено на Desktop 31.5) окно *Extras → Plugins* даёт
выбрать только встроенные плагины, а флага `--enable-plugins` больше нет.

**Проще всего — запускать draw.io Desktop через скрипт** (плагин подгрузится сам):

```sh
npm start                              # собрать плагин и открыть draw.io
node scripts/start-drawio.js file.drawio   # открыть конкретный файл
```

Скрипт запускает draw.io с портом отладки Chromium (только `127.0.0.1:9339`, меняется
переменной `DRAWIO_DEBUG_PORT`) и выполняет плагин в окне редактора. **Не закрывайте окно
терминала**, пока работаете: скрипт остаётся «мостом» — подгружает плагин в новые окна
draw.io и выполняет подключения к базе; сам завершается, когда draw.io закрыт.
Если draw.io уже запущен этим скриптом (терминал закрыли) — `npm start` просто подключится
к нему заново. Путь к программе ищется в `%LOCALAPPDATA%\Programs\draw.io`
и `Program Files`, либо задаётся переменной `DRAWIO_EXE`. Версия из Microsoft Store
не подходит; обычная ставится командой `winget install JGraph.Draw`.

**Вручную через консоль** (в т.ч. в браузере) — плагин, загруженный в уже открытый
редактор, срабатывает сразу:

1. Скопируйте плагин в буфер обмена:
   ```powershell
   Get-Content "dist\sql-er-plugin.js" -Raw -Encoding UTF8 | Set-Clipboard
   ```
2. Откройте консоль разработчика:
   - **draw.io Desktop** — *Помощь → Open Dev Tools* (в классическом интерфейсе);
   - **браузер (app.diagrams.net)** — F12.
3. Вкладка **Console** → вставьте (Ctrl+V) → Enter. Если консоль попросит, сначала наберите `allow pasting`.

Плагин действует до закрытия окна/вкладки, после перезапуска шаг повторяется.
Загрузка из базы так не работает — для неё нужен мост `npm start`.

## Использование

*Упорядочить → Вставить → Из SQL (ER-диаграмма)…* (Arrange → Insert)

1. Выберите **источник**:
   - **Вставить SQL** — вставьте DDL в поле;
   - **Файл .sql** — «Выбрать файл…» (или перетащите файл в поле);
   - **База PostgreSQL** — строка подключения `postgres://user@host:5432/db`, пароль
     (отдельным скрытым полем), схемы через запятую → «Подключиться».
     Работает, только если draw.io запущен через `npm start` (см. ниже «Как устроено
     подключение к базе»).

   В любом случае SQL оказывается в поле — его можно поправить перед вставкой.
   Под полем сразу видно, сколько найдено таблиц, связей и индексов, и предупреждения.

   **Выбор таблиц.** Справа от поля — список таблиц схемы с галочками (по умолчанию
   отмечены все): поиск по имени, «Все» / «Ни одной» (для видимых по поиску),
   «+ связанные» (добавить таблицы, связанные с отмеченными). Вставляются только
   отмеченные; внешние ключи на неотмеченные таблицы остаются в строках колонок
   (`REFERENCES …`), но без линий. Отметки сохраняются, если поправить SQL.
2. Галочки:
   - **Заменить содержимое страницы** — очистить страницу перед вставкой
     (иначе диаграмма встанет под уже нарисованным);
   - **Ограничения как в SQL** — после типа всё, что написано у колонки (`NOT NULL`, `DEFAULT …`, `CHECK (…)`…);
     если выключить — короткие метки PK/FK/UQ/AI;
   - **Показывать NULL** — в режиме коротких меток помечать колонки без `NOT NULL`;
   - **Показывать индексы** — блок индексов под колонками;
   - **ENUM**, **Представления**, **Комментарии** — показывать ли эти объекты;
   - **Компактно** — в таблицах только ключи (PK, FK), колонки, на которые ссылаются, и колонки
     типа ENUM; остальные — строкой «⋯ ещё N колонок» (список — в подсказке). Экспорт в SQL и
     сравнение со схемой видят таблицу целиком;
   - **Группы** — рамки вокруг таблиц: *по префиксам* имён (`course_modules`, `course_lessons`,
     `courses` → «course»; по умолчанию), *по схемам* (`billing.*`, если схем больше одной)
     или *нет*. Группа — минимум две таблицы.

   Раскрывающийся блок **«Обозначения на диаграмме»** внизу окна — легенда всех значков.
3. «Вставить». Вставка отменяется одним Ctrl+Z.

**Обновить на странице.** Если схема изменилась, не вставляйте диаграмму заново —
загрузите новый SQL (любым способом) и нажмите «Обновить на странице»:
- таблицы, которые уже есть, остаются на своих местах и сохраняют ручные правки стиля
  (цвет и т.п.); у них заменяется содержимое — колонки, ограничения, индексы;
- новые таблицы встают справа от родителя (или слева от ребёнка, иначе — под диаграммой)
  на свободное место и выделяются;
- таблицы, которых нет в новой схеме, не удаляются, а помечаются пунктиром и
  полупрозрачностью — удалите сами, если не нужны; вернутся в схему — пометка снимется;
- связи пересобираются и прокладываются заново.

Таблицы, которые уже на странице, обновляются всегда; галочки в списке решают, какие
**новые** таблицы добавить. Неотмеченные таблицы схемы удалёнными не считаются.

Всё — одна операция (один Ctrl+Z). Таблицы узнаются по скрытой метке с именем, поэтому
подпись можно переименовать. Работает для диаграмм, вставленных этой версией плагина.

**Сравнить с диаграммой.** Загрузите в окно схему любым способом (база, файл, вставка) и
нажмите «Сравнить с диаграммой» — отчёт покажет, чем диаграмма на текущей странице отличается
от этой схемы:
- таблицы только на диаграмме / только в схеме (и подсказка «возможно, переименована»);
- колонки: добавлена/удалена, тип, NOT NULL, DEFAULT, автоинкремент;
- первичный ключ, UNIQUE, внешние ключи, индексы (по содержанию; разное имя — пометкой);
- ENUM (набор и порядок значений), представления (есть ли и колонки);
- CHECK — если выражения отличаются только записью, пометка «~ возможно отличается»;
- комментарии — по галочке «Учитывать комментарии».

Сравнивается смысл, а не запись: `INT` = `integer`, `SERIAL` = `integer DEFAULT nextval(…)`,
`TIMESTAMPTZ` = `timestamp with time zone`, ограничения у колонки и у таблицы (`CONSTRAINT … UNIQUE`)
считаются одинаковыми, имена ограничений не сравниваются, выражения из базы упрощаются.
На диаграмме различия временно подсвечиваются: красным — расходящиеся таблицы и колонки,
зелёным — таблицы, которых в схеме нет; подсветка снимается при закрытии отчёта.
«Обновить диаграмму из схемы» в отчёте — то же, что «Обновить на странице».
База при этом не меняется (мост работает только на чтение).

**Экспорт в SQL / Mermaid.** *Упорядочить → Экспорт в SQL / Mermaid (SQL ER)…* собирает SQL из того, что сейчас
нарисовано на странице, с вашими правками: переименованные таблицы (ссылки `REFERENCES` на них
тоже получают новое имя), исправленные и добавленные вручную строки колонок, ограничения и
индексы из нижнего блока, ENUM, комментарии; связь, нарисованная вручную между строками двух
таблиц, становится `ALTER TABLE … ADD FOREIGN KEY`. Таблицы идут в таком порядке, чтобы
`REFERENCES` указывал на уже созданную. Подписи в режиме коротких меток переводятся обратно
в `PRIMARY KEY` / `UNIQUE` / `NOT NULL`. Для представлений — комментарий с колонками
(текст запроса на диаграмме не хранится). В окне — «Копировать» и «Сохранить».

Формат **Mermaid (erDiagram)** — для вставки схемы в Markdown (GitHub, GitLab её рисуют):
сущности с типами, `PK` / `FK` / `UK` и комментариями, связи `||` / `|o` → `o{` / `o|`
(сплошная линия — FK входит в PK ребёнка). Галочка «для Markdown» оборачивает текст в
```` ```mermaid ````. Типы и имена приводятся к допустимым в Mermaid (`numeric(12,2)` →
`numeric(12_2)`); ENUM и представления — комментариями `%%`. Сохраняется в `.mmd` / `.md`.

**Перепроложить связи.** Если таблицы передвинули, у линий остаются изломы на старых
местах. *Упорядочить → Перепроложить связи (SQL ER)* заново прокладывает все связи
плагина на странице по текущим положениям таблиц (в т.ч. справа налево и внутри одного
столбца). Длинные связи идут через те же «окна» между таблицами, что и при вставке,
пока окно свободно; если на его место поставили таблицу — в обход по коридору.
Рамки групп тоже перестраиваются вокруг таблиц. Одна операция — один Ctrl+Z.
Таблицы не должны накладываться друг на друга.

**Подсветка связей.** Выделите таблицу (или её строку) — её связи и соседние таблицы
обводятся красным. Обводка временная, диаграмму не меняет. Выключается пунктом
*Упорядочить → Подсветка связей (SQL ER)*; выбор запоминается.

## Как устроено подключение к базе

Страница draw.io не может сама подключиться к PostgreSQL: у неё нет сокетов, а политика
безопасности draw.io (`connect-src`) запрещает запросы даже к `localhost`. Поэтому
подключается скрипт запуска: он регистрирует в окне функцию (`Runtime.addBinding`),
плагин передаёт в неё запрос, скрипт читает схему драйвером `pg` и возвращает DDL.

- Только чтение: сессия `default_transaction_read_only`, одни `SELECT` по `pg_catalog`
  (`bridge/introspect.js`); данные таблиц не читаются.
- Берутся перечисления (`pg_enum`), представления (`pg_get_viewdef`), комментарии
  (`obj_description`, `col_description`), обычные и секционированные таблицы (без самих секций), колонки
  (`format_type`, `DEFAULT`, `IDENTITY`, `GENERATED … STORED`), ограничения
  (`pg_get_constraintdef`), индексы (`pg_get_indexdef`, кроме созданных под PK/UNIQUE).
  `integer DEFAULT nextval(…)` показывается как `serial`.
- Выражения в `CHECK`/`DEFAULT` PostgreSQL хранит в нормализованном виде; частые случаи
  возвращаются к привычному: `= ANY (ARRAY[…])` → `IN (…)`, `<> ALL (…)` → `NOT IN (…)`,
  `'draft'::text` → `'draft'`, `(0)::numeric` → `0`, лишние внешние скобки убираются.
  Остальное (например, `BETWEEN`, который PostgreSQL хранит как `>= AND <=`) — как в базе.
- Пароль не сохраняется; запоминаются только способ, строка подключения без пароля и схемы.

## Что понимает парсер

- `CREATE TABLE [IF NOT EXISTS]`, в т.ч. `TEMP`/`UNLOGGED`, схемы (`public.` в названии скрывается), `"имена в кавычках"`
- типы любого вида: `VARCHAR(255)`, `NUMERIC(10, 2)`, `TEXT[]`, `TIMESTAMP WITH TIME ZONE`
- `SERIAL`/`BIGSERIAL`, `GENERATED … AS IDENTITY`, `DEFAULT nextval(…)`
- ограничения колонки: `PRIMARY KEY`, `NOT NULL`, `UNIQUE`, `DEFAULT …`, `REFERENCES t[(col)]`, `CHECK (…)`
- ограничения таблицы: `PRIMARY KEY (a, b)`, `UNIQUE (a, b)`, `FOREIGN KEY (…) REFERENCES …`, `CONSTRAINT имя …`
- `ALTER TABLE [ONLY] … ADD [COLUMN] [IF NOT EXISTS] …`, `ADD CONSTRAINT …`,
  `ALTER COLUMN … SET DEFAULT nextval(…)` / `ADD GENERATED … AS IDENTITY` — то есть вывод `pg_dump --schema-only`
- комментарии `--`, `/* */` (вложенные), строки `'…'`, `E'…'`, `$$…$$` не ломают разбор

- `CREATE [UNIQUE] INDEX [CONCURRENTLY] [IF NOT EXISTS] [имя] ON [ONLY] t [USING метод] (…) [INCLUDE (…)] [WHERE …]`;
  уникальный индекс по колонке без `WHERE` помечает её UQ и учитывается для связи «один к одному»

- `CREATE TYPE … AS ENUM (…)`, `ALTER TYPE … ADD VALUE [IF NOT EXISTS] '…' [BEFORE | AFTER '…']`,
  `ALTER TYPE … RENAME VALUE`
- `CREATE [OR REPLACE] [MATERIALIZED] VIEW [IF NOT EXISTS] имя [(колонки)] AS SELECT …`:
  колонки — из списка или из `SELECT` (`AS x`, `t.col` → `col`, `f(x)` → `f`, `*`);
  зависимости — таблицы из `FROM` / `JOIN` на любой глубине, кроме имён из `WITH`
- `COMMENT ON TABLE | VIEW | MATERIALIZED VIEW | TYPE | COLUMN … IS '…' | NULL`
- комментарии через `--` (если нет `COMMENT ON` для того же объекта):
  - колонка — `--` в конце её строки (`name TEXT,   -- …`) или строками прямо над ней;
  - таблица, ENUM, представление — строками прямо над `CREATE …` (без пустой строки между)
    или в конце строки `CREATE TABLE x (   -- …`;
  - заголовки разделов, отделённые пустой строкой, и строки из одних `===` / `---` не считаются;
    у заголовков вида `-- ---------- курсы ----------` рамка из чёрточек убирается.
  В базе `--`-комментариев нет — они есть только в тексте SQL (файл или вставка).

**MySQL и SQLite** распознаются сами, без переключателя:
- `` `имена` `` и `[имена]`; в MySQL регистр имён сохраняется (`Users` ≠ `users`);
- `AUTO_INCREMENT` / `AUTOINCREMENT`, `UNSIGNED`, `CHARACTER SET …`, `ON UPDATE …`;
- `COMMENT '…'` у колонки и `COMMENT='…'` у таблицы — как комментарии (подсказка / строка под заголовком);
- `KEY` / `INDEX` / `UNIQUE KEY` / `FULLTEXT KEY` внутри `CREATE TABLE` и `ALTER TABLE … ADD INDEX`;
- `FOREIGN KEY имя (…)`, `ENGINE=…`, `WITHOUT ROWID`, дамп `mysqldump` (SET, LOCK, INSERT пропускаются);
- `#`-комментарии — только если в тексте есть признаки MySQL (обратные кавычки, `ENGINE=`, `AUTO_INCREMENT`).

Всё остальное (функции, триггеры, `INSERT`, `GRANT`, `SET` …) пропускается.

## Безопасность

- **Порт отладки.** `npm start` открывает draw.io с портом отладки Chromium на
  `127.0.0.1:9339` — только для этого компьютера, из сети недоступен. Пока draw.io запущен
  так, любая программа на этом компьютере может управлять окном draw.io через этот порт.
  Если это неприемлемо (общий компьютер), запускайте draw.io обычным образом, а плагин
  подгружайте вручную через консоль (см. выше).
- **База — только чтение.** Сессия `default_transaction_read_only`, только `SELECT` по
  `pg_catalog`; каждый запрос — не дольше 30 с (`statement_timeout`). В `pg_stat_activity`
  подключение видно как `drawio-sql-er`. Для надёжности дайте плагину отдельного
  пользователя без прав на запись.
- **Пароль** вводится отдельным полем и нигде не сохраняется; в терминале моста пишутся
  только хост, порт и имя базы.
- **Чужие .drawio.** Подписи диаграммы при экспорте и сравнении разбираются без выполнения
  HTML (`DOMParser`), поэтому разметка в подписях чужого файла не выполняется.

## Известные ограничения

- Свои плагины в draw.io Desktop официально не подключаются — только через `npm start` или
  консоль разработчика. В app.diagrams.net сторонние плагины запрещены.
- Подключение к базе — только PostgreSQL и только через мост `npm start`.
- У представлений из SQL-файла нет типов колонок (их знает только база).
- Составные типы (`CREATE TYPE … AS (…)`), домены, функции и триггеры не показываются.
- `--`-комментарии есть только в тексте SQL; в базе — только `COMMENT ON`.
- Экспорт в SQL выдаёт синтаксис PostgreSQL (и для диаграмм из MySQL/SQLite).
- «Обновить на странице» работает для диаграмм, вставленных этой версией плагина;
  «окна» длинных связей для «Перепроложить связи» сохраняются начиная с версии 1.0.0.

## Устройство

```
src/parser.js    SQL DDL (PostgreSQL, MySQL, SQLite) → модель { tables, relations, warnings }
src/drawio.js    модель → XML графа draw.io (строки, размеры, стили)
src/layout.js    раскладка: столбцы, порядок без пересечений, «окна», группы-блоки, сетка
src/routing.js   трассировка связей по дорожкам и коридорам
src/placement.js места для новых таблиц при обновлении
src/page.js      операции над страницей: «Перепроложить связи», «Обновить», снимок для экспорта
src/export.js    экспорт диаграммы в SQL
src/mermaid.js   экспорт в Mermaid (erDiagram)
src/legend.js    легенда обозначений в окне плагина
src/diff.js      сравнение двух схем (нормализация типов, ограничений, выражений)
src/sqltext.js   упрощение выражений PostgreSQL (общее для моста и сравнения)
src/groups.js    группы (рамки) по схемам и префиксам
src/highlight.js подсветка связей выбранной таблицы
src/select.js    выбор части таблиц схемы, «+ связанные»
src/plugin.js    пункт меню, окно, вставка в граф
scripts/build.js сборка src/ в один файл dist/sql-er-plugin.js
scripts/check.js проверка перед выпуском (npm run check)
scripts/start-drawio.js  запуск draw.io + подгрузка плагина + мост к базе
bridge/introspect.js     чтение структуры PostgreSQL → DDL
examples/        примеры SQL для проверки
```
