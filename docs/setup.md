## Какой способ выбрать

|                     | Docker                              | draw.io Desktop                | app.diagrams.net                              |
| ------------------- | ----------------------------------- | ------------------------------ | --------------------------------------------- |
| Что нужно           | Docker                              | draw.io Desktop, Node.js 22.9+ | только браузер                                |
| Где работает        | `http://localhost:8080`             | окно draw.io Desktop           | https://app.diagrams.net/                     |
| Плагин подключается | сам                                 | сам, через `npm start`         | вставкой в консоль, после каждой перезагрузки |
| Подключение к базе  | через сервер в контейнере           | через мост в терминале         | нет                                           |
| Файлы               | скачиваются / открываются браузером | как обычно в draw.io           | как обычно на сайте                           |

Чтобы просто попробовать без установки, используйте **сайт**. Для постоянной работы в браузере
подходит **Docker**, для работы с файлами `.drawio` на диске — **Desktop**.

Для Docker и Desktop сначала скачайте проект:

```sh
git clone https://github.com/valeragav/drawio-sql-er.git
cd drawio-sql-er
```

## Docker

```sh
docker compose up -d
```

Откройте **http://localhost:8080**. Это draw.io 31.4.6 с уже подключённым плагином и сервером
для подключения к базе, всё на одном адресе.

- Остановить — `docker compose down`.
- Диаграммы сохраняются как обычно: *Файл → Сохранить* скачивает `.drawio`. Сервер ничего
  не хранит.
- Порт и другие параметры задаются в [`.env`](#настройки-env).
- База на этом же компьютере доступна из контейнера как `host.docker.internal`, подробнее —
  в разделе [«Подключение к базе»](#подключение-к-базе).

## draw.io Desktop

Нужны:

- [draw.io Desktop](https://www.drawio.com/). Подходит обычная версия, а не версия из
  Microsoft Store, которая не принимает нужные флаги запуска. Установка через winget:
  `winget install JGraph.Draw`;
- [Node.js](https://nodejs.org) 22.9 или новее.

```sh
npm install
npm start
```

Откроется draw.io с плагином.

- **Не закрывайте окно терминала**, пока работаете: через него плагин подгружается в новые
  окна draw.io и подключается к базе. Когда закроете draw.io, скрипт завершится сам.
- Если draw.io уже был открыт обычным способом, закройте его перед `npm start`.
- Чтобы открыть конкретный файл: `node scripts/start-drawio.js схема.drawio`.
- Если draw.io установлен в нестандартное место, путь к нему задаётся в `DRAWIO_EXE`
  (см. [`.env`](#настройки-env)).

Почему через `npm start`, а не через *Дополнительно → Плагины*: draw.io разрешает там
только встроенные плагины. Поэтому скрипт запускает Desktop со служебным портом отладки и
подгружает плагин через него.

## Сайт app.diagrams.net

Штатно (*Extras → Plugins*) сайт подключает только встроенные плагины, но плагин можно
выполнить в консоли браузера.

1. Соберите плагин и скопируйте его в буфер обмена (в папке проекта):
   ```powershell
   npm run build
   Get-Content "dist\sql-er-plugin.js" -Raw -Encoding UTF8 | Set-Clipboard
   ```
   В macOS: `pbcopy < dist/sql-er-plugin.js`, в Linux: `xclip -sel clip < dist/sql-er-plugin.js`.
2. Откройте https://app.diagrams.net/, нажмите **F12** и перейдите на вкладку **Console**.
3. Нажмите в консоли **Ctrl+V**, затем **Enter**.
   - Если вместо этого появилось жёлтое предупреждение «Don't paste code…» («Не вставляйте
     код…»), напечатайте вручную `allow pasting`, нажмите **Enter**, затем снова **Ctrl+V**
     и **Enter**.
4. Если консоль ответила `undefined`, плагин загружен и консоль можно закрыть (F12). Красная
   ошибка означает, что что-то пошло не так: например, в буфер попал не весь файл.
5. Откройте меню **Упорядочить → Вставить → «Из SQL (ER-диаграмма)…»**.

На сайте работает всё, кроме **подключения к базе**: сайт запрещает странице обращаться к
вашему компьютеру. Плагин действует до перезагрузки вкладки, после неё шаги 2–4 нужно
повторить.

Так же плагин можно подгрузить и в обычный draw.io Desktop: *Помощь → Open Dev Tools* → Console.

## Сервер без Docker

Тот же сервер, что в Docker-образе, можно запустить напрямую: `npm run serve`. Ему нужна
папка с веб-версией draw.io (webapp из [jgraph/drawio](https://github.com/jgraph/drawio)),
путь к ней указывается в `DRAWIO_DIR` в `.env`:

```sh
npm install
cp .env.example .env    # и укажите DRAWIO_DIR
npm run serve           # http://127.0.0.1:8080
```

## Настройки (.env)

Все настройки необязательные. Скопируйте образец и поправьте нужное:

```sh
cp .env.example .env
```

В `.env.example` каждая переменная описана. `.env` не попадает в git.

| Переменная          | По умолчанию | Способ     | Для чего                                                         |
| ------------------- | ------------ | ---------- | ---------------------------------------------------------------- |
| `SQL_ER_PORT`       | `8080`       | Docker     | порт в браузере                                                  |
| `SQL_ER_BIND`       | `127.0.0.1`  | Docker     | `0.0.0.0` открывает доступ из сети (только с HTTPS, см. ниже)    |
| `SQL_ER_DB`         | `on`         | Docker     | `off` выключает подключение к базе                               |
| `DRAWIO_DIR`        | —            | serve      | папка с веб-версией draw.io (обязательна)                        |
| `PORT`, `HOST`      | `8080`, `127.0.0.1` | serve | порт и адрес сервера                                          |
| `DRAWIO_EXE`        | —            | Desktop    | путь к `draw.io.exe`, если он не нашёлся сам                     |
| `DRAWIO_DEBUG_PORT` | `9339`       | Desktop    | служебный порт, через который подгружается плагин                |

Чтобы изменения вступили в силу: в Docker выполните `docker compose up -d`, для Desktop
перезапустите `npm start`.

## Подключение к базе

Работает в Docker и в Desktop через `npm start`. На сайте app.diagrams.net недоступно.

В окне плагина выберите источник **«База PostgreSQL»** и заполните поля:

1. строка подключения:
   ```
   postgres://user@host:5432/database
   postgres://user@host:5432/database?sslmode=require
   ```
2. пароль — отдельным полем;
3. схемы через запятую, по умолчанию `public`.

Затем нажмите **«Подключиться»**. Структура базы превратится в SQL в поле окна, и дальше
всё работает как при вставке SQL.

**Какой хост указывать:**

| Где база                       | Docker                                 | Desktop     |
| ------------------------------ | -------------------------------------- | ----------- |
| на этом же компьютере          | `host.docker.internal`                 | `localhost` |
| в другом контейнере            | имя сервиса в общей сети Docker        | `localhost` и проброшенный порт |
| на другом сервере              | адрес сервера                          | адрес сервера |

Внутри контейнера `localhost` означает сам контейнер, поэтому в Docker нужен
`host.docker.internal`.

**Что происходит при подключении:**

- Плагин **только читает структуру**: таблицы, ключи, ограничения, индексы, ENUM,
  представления, комментарии. Данные таблиц не читаются, база не меняется. Достаточно
  пользователя с правом подключения; для надёжности заведите отдельного пользователя без
  прав на запись.
- **Пароль не сохраняется** ни в браузере, ни в журнале. Запоминаются только строка
  подключения без пароля и список схем.
- Выражения, которые PostgreSQL хранит по-своему, возвращаются к привычному виду:
  `= ANY (ARRAY[…])` → `IN (…)`, `'draft'::text` → `'draft'`. Остальное показывается как в
  базе: например, `BETWEEN` база хранит как `>= AND <=`.
- Одинаковые ограничения под разными именами показываются все, как в базе, с предупреждением.

## Безопасность

- Плагин работает с базой **только на чтение**. Каждый запрос ограничен 30 секундами, в
  списке подключений (`pg_stat_activity`) он виден как `drawio-sql-er`.
- **Docker** по умолчанию доступен только с этого компьютера. Сервер подключается к той
  базе, которую укажет открывший страницу, и пароль передаётся ему в запросе. Поэтому,
  открывая доступ коллегам (`SQL_ER_BIND=0.0.0.0`), ставьте впереди прокси с HTTPS и
  авторизацией (nginx, Caddy, Traefik) или выключите подключение к базе (`SQL_ER_DB=off`).
- **`npm start`** открывает у draw.io служебный порт `127.0.0.1:9339`. Из сети он
  недоступен, но пока draw.io запущен так, им может воспользоваться любая программа на этом
  компьютере. На общем компьютере подгружайте плагин через консоль.
- Разметка в подписях чужих файлов `.drawio` не выполняется.

## Обновление и удаление

**Обновление:**

```sh
git pull
docker compose up -d --build   # Docker
npm install                    # Desktop: затем снова npm start
```

В Docker после обновления перезагрузите страницу с очисткой кэша (Ctrl+F5). На сайте
пересоберите плагин (`npm run build`) и вставьте его в консоль заново.

**Удаление:** `docker compose down --rmi all` (Docker, удалит и образ `drawio-sql-er`), затем удалите папку проекта.
Плагин ничего не устанавливает в draw.io Desktop: без `npm start` тот запускается как обычно.
